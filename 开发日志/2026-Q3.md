## 开发一个web server，Transfer Hub

1. 项目目标

在 ~/workdir/{transfer_hub} 上开发一个轻量级 Web 文件与消息中转服务。
能支持 不同设备（PAD、手机、PC）只需通过浏览器访问同一个网页，即可实现：

1. 文件上传、下载和管理。
2. 不同设备之间的文本发送与接收。
3. 剪贴板内容中转。
4. 后续支持多设备扩展。
核心原则：轻量、简单、易用、本地部署。
5. 提供json配置文件（包括上传下载目录地址、临时消息的历史保留条数等）


2. 页面设计

一个页面，两个主要功能区域。

2.1 文件管理区

文件列表: 文件上传、下载、删除。 支持（多选）多文件上传/下载。支持文件夹上传/下载。
显示文件名、大小、上传时间。支持图片和文本预览。支持拖拽上传。

2.2 临时消息区
多行文本输入框。
发送按钮：将文本发送到服务器。
接收按钮：获取服务器上的最新消息。
复制按钮：复制当前文本到系统剪贴板。
清空按钮。

支持手动选择文本，手动复制/粘贴。
消息采用历史记录模式，不采用单一文本覆盖模式。
接收消息后不自动删除，避免信息丢失。历史消息保留50条（可配置）

## 开发一个web server， Notes Browser

1. 项目目标
在线网页文本浏览器，要求支持markdown文本的渲染和显示

2. 页面设计
- 支持缩进/展开的左边栏，显示文件夹目录。
- 右边文本区域显示文本，对*.md 渲染为markdown格式
- 支持右边文本区域的在线文本编辑，支持*.md文本的 markdown语法
- 支持实时保存文本。

3. 支持json配置，当前支持对 notes_dir 的设置，当前设置为 ~/workdir/workboard/notes/
4. 同步按钮
- 左边栏最下方支持 扩展菜单>> ，点击后弹出子菜单
- 子菜单中增加 “git同步”按钮
- 点击git同步按钮，在 ${notes_dir} 中执行 git pull; git add .; git commit -m"update"; git push等操作，并在页面最下面显示临时状态栏，显示git 命令执行结果。 同步失败要显示的报错。

## 开发一个web server， Work Board

1. 项目目标
作为工作面板，在主页面上汇总所有子应用（图标+文字的方式），包括 notes_browser，transfer_hub，webui

2. 页面设计
- 在页面上汇总呈现各个子应用（图标帮我设计），当前支持 notes_browser（名称为Notes），transfer_hub（名称为TransHub），webui（LocalWebui）
- 每个应用图标上显示状态小圆灯（绿色表示正在运行，灰色是停止，红色是异常，例如启动失败或者联网失败等）
- 页面上增加设置按钮，允许调整子应用顺序。web页面中每行最多显示5个子应用，按顺序显示，并自适应不同设备访问（如手机、pad、PC等）。

3. 主要设计
- 支持json格式配置文件，在json配置中注册各个子应用，包括子应用的 服务脚本，用于 start stop status命令，以及子应用端口等。
- 点击某个图标时，弹出子菜单，包含 打开，启动，停止，状态等按钮：
	-- 打开按钮： 使用新的web页签打开该子应用的服务地址，并自动跳转到该页签。例如当前workboard的ip是 tailscale网络 100.x.x.x，则打开 http://100.x.x.x:子应用端口。如果当前workboard的ip是 内网 192.168.x.x，则打开 http://192.168.x.x:子应用端口
	-- 启动按钮： 如果没有启动，点击启动，则后台启动子应用服务。 如果已经启动，默认启动按钮是灰色不可按。
	-- 停止按钮： 如果已经启动或处于异常，点击停止，则后台停止子应用服务。 如果未启动，默认停止按钮是灰色不可按。
	-- 状态按钮： 点击弹窗显示状态信息。
- 所有弹窗窗口 右上角有个×， 点击可以关闭弹窗。
